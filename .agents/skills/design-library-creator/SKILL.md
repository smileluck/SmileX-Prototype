# /design-library-creator

> 从任意 UI 来源生成符合 Nimbus Core 契约的设计系统包（tokens + components + ui_kits）。

`trae-ui-example/` 是**只读参考示例**。本技能产出独立的设计库到 `./design-systems/{name}/`。

## Usage

```
/design-library-creator <source> [--name <lib-name>] [--output <path>] [--kit <type1,type2>]
/design-library-creator refine <lib-path>                       # 子命令：refine-library
/design-library-creator expand <lib-path> <slug> [--source <hint>] # 子命令：expand-components
/design-library-creator kit <lib-path> <type>                   # 子命令：generate-additional-kit
```

**Source 类型**：
- 本地路径：`./node_modules/element-plus`、`./previews/buttons.html`
- URL：`https://element-plus.org`
- 图片：`./screenshot.png`、`./mockup.fig.png`
- 库标识：`element-plus` / `ant-design` / `mui` / `tailwind` / `unocss` / `chakra-ui` / `naive-ui`

**示例**：
```
/design-library-creator ./previews/ --name nimbus-core
/design-library-creator https://element-plus.org --name element-core --kit dashboard
/design-library-creator ./screenshot.png --name ide-minimal --kit dev-explorer
/design-library-creator naive-ui --name naive-core --kit dashboard
/design-library-creator refine ./design-systems/nimbus-core
/design-library-creator expand ./design-systems/nimbus-core tooltip
/design-library-creator kit ./design-systems/nimbus-core mobile
```

## Library Layout（产出结构）

> 本技能的产出严格对齐 `trae-ui-example/` 的契约。下表展示库的目录结构：

```
<lib-root>/                     # design-systems/{name}/
├── SKILL.md                    # 库专属的"设计规范"（简洁版）
├── README.md                   # 库专属的"人类指南"（含 Downstream Consumption Guide）
├── colors_and_type.css         # Token 权威源（verbatim from source）
├── css.json                    # Token 机器可读投影
├── components.css              # 聚合组件类（AUTO-GENERATED，禁手改）
├── icons.js                    # 可选：图标 sprite 渲染器
├── uikit-plan.json             # 组件白名单 + 优先级 + slot
├── library-consumption.json    # 下游消费顺序
├── assets/
│   └── icons/                  # 115+ bundled SVG icons
├── components/
│   ├── index.json              # 组件清单 + ui-kits 索引
│   └── {slug}.json             # 每个组件 1 个契约
├── preview/
│   └── component-{slug}.html   # 每个组件 1 个预览页
└── ui_kits/
    └── {type}/
        ├── index.html          # 单文件 React 18 showcase
        └── quality-report.json # 必填字段报告
```

> `trae-ui-example/` 是**范本**（已存在的 Nimbus Core 实现），不是技能产物。新生成的库（例如 `design-systems/naive-core/`）必须按本技能自己的契约写自己的 `SKILL.md` / `README.md`，不能复制 trae-ui-example 的内容。

> `components.css` is regenerated by `scripts/extract-components-css.mjs`, scanning every `preview/component-*.html` for CSS between `/* @component-css-start */` and `/* @component-css-end */` markers.

## 4 阶段流水线（必走，不可跳）

```
Phase 1: 来源解析      → source-brief.json（中间产物，不进库）
Phase 2: Token 规范化  → colors_and_type.css + css.json
Phase 3: 组件拆解      → components/*.json + preview/component-*.html
Phase 4: 聚合 + UIKit  → components.css（脚本生成） + components/index.json + uikit-plan.json
                          + library-consumption.json + ui_kits/{type}/
```

每个阶段都必须**主动遍历来源的所有组件**（不是用户给的列表），从源头枚举：
- 本地源码：扫 `src/<component>/` 目录
- URL：访问组件库官方导航，枚举所有组件页面
- 图片：根据视觉识别列出所有可区分的控件
- 库标识：用内置的源清单（95+ components for naive-ui）枚举

最终目标：**生成 24+ 组件 + 1+ UIKit**（与 Nimbus Core 持平）。

## 🔴 硬约束（必须遵守，违反 = 拒绝写入）

### 1. Token 命名 verbatim
- ✅ Token **保留源命名**（不重命名、不缩放、不发明）
- ❌ **禁止**引入 `--color-*` 等便携别名
- ❌ **禁止**新增色彩刻度（除非用户明确要求）
- ✅ 组件直接消费 `var(--bg-*)`、`var(--text-*)`、`var(--status-*-*)`、`var(--brand-*-*)`

### 2. colors_and_type.css 头部
- ✅ 必须包含 `/* @dark-only */` 标记（除非用户明确要 light 主题）
- ✅ 必须包含分组优先级注释：`/* @group-priority: brand-green, status, brand-blue, brand-purple, brand-yellow */`

### 3. css.json 字段
- ✅ 必填字段：`color`、`font`、`radius`、`spacing`
- ✅ 保留空桶：`shadow`、`size`（按 spec 保留，即使无值）

### 4. 组件 JSON 契约（schemaVersion: 2）
- ✅ 必填字段：`schemaVersion`、`slug`、`name`、`category`、`tokensConsumed`、`domAnatomy`、`provenance`
- ✅ `domAnatomy.root.tag/class` 必填
- ✅ `tokensConsumed` 必须是 Phase 2 已定义的 token（不允许引用未定义 token）

### 5. preview HTML 结构
- ✅ `<head>` 必须包含 `<link rel="stylesheet" href="../colors_and_type.css" />`
- ✅ JetBrains Mono 通过 Google Fonts `<link>` 引入（不下载到本地）
- ✅ `<style>` 必须有 `/* @component-css-start */` 与 `/* @component-css-end */` 标记
- ✅ **预览页 chrome**（reset、body padding、`.pv-*`）必须在 `@component-css-start` **之上**
- ✅ **组件 CSS**（`.ds-*` 类）必须在两个标记**之间**
- ❌ **禁止**外部 API 调用（fetch / XHR / 第三方 CDN JS 库，仅允许 Babel Standalone + JetBrains Mono Google Fonts）

### 6. 组件 CSS 命名
- ✅ 类前缀统一 `.ds-*`（design system）
- ✅ 变体用 BEM：`--{intent}`、`--{size}`、`--{state}`
- ❌ **禁止**硬编码 hex / rem / px（必须用 `var(--token)`）

### 7. components.css
- ❌ **禁止**手改 `components.css`
- ✅ 必须由 `scripts/extract-components-css.mjs` 生成
- ✅ 顶部必须包含 `/* AUTO-GENERATED ... do not edit by hand */` 注释

### 8. ui_kits
- ✅ 容器必须 `max-width: 1184px`（**硬约束**：UIKit 是 showcase，不是 page template）
- ✅ 引用 `../../colors_and_type.css` + `../../components.css`
- ✅ React 18 + Babel Standalone CDN（仅这一个 CDN 例外）
- ✅ 每个 ui-kit 必须有 `quality-report.json`

### 9. trae-ui-example 只读
- ❌ **禁止**修改、追加、删除 `trae-ui-example/` 下任何文件
- ❌ **禁止**把生成结果写到 `trae-ui-example/`

### 10. 输出目录
- 默认 `./design-systems/{name}/`
- 已存在且非空 → 询问 `--force` 后覆盖；默认拒绝

## 4 类来源适配器

### A. 本地源码（`source-local`）
- **触发**：source 是目录路径或文件路径
- **工具**：Read / Grep / Glob + Node 脚本（`postcss` 解析 CSS vars）
- **组件枚举策略**：扫 `src/<component>/` 完整目录树，列出所有组件 slug

### B. URL / 网站（`source-url`）
- **触发**：source 以 `http://` 或 `https://` 开头
- **工具**：`integrated_browser` MCP（navigate → snapshot → evaluate → screenshot）
- **组件枚举策略**：访问组件库导航侧栏，列出所有组件页面链接

### C. 图片（`source-image`）
- **触发**：source 是 `.png` / `.jpg` / `.jpeg` / `.webp` / `.svg`
- **工具**：Read 工具读图 + 多模态视觉理解 + 抽样取色
- **组件枚举策略**：逐区域视觉识别控件类型（按钮、表单、表格、卡片、标签等）

### D. 主流组件库（`source-library`）
- **触发**：source 是已知库标识
- **工具**：内置源清单适配器表（见 `references/source-adapters.md`）
- **组件枚举策略**：直接读内置清单（如 naive-ui 有 95 个组件，按优先级排序取前 24）

**详细解析策略**：见 `references/source-adapters.md`

## Phase 1: 来源解析（详）

1. 识别 source 类型（A/B/C/D）
2. **主动枚举所有组件**（不要等用户列）：
   - 本地源码：扫 `node_modules/<lib>/src/` 或 `src/`
   - URL：访问组件库首页 → 抓导航树
   - 图片：视觉识别每个 UI 区域
   - 库标识：内置清单
3. 按 **固定优先级 + 场景相关性** 筛选 24+ 核心组件：
   - 核心：buttons / menu / breadcrumb / card / tag / table / pagination / alert / avatar / progress / dialog / dropdown / popover / tooltip / notification / form / forms / select / input-number / badge / empty / tabs / button-group / atoms
4. 提取每个组件的：
   - name（中文/英文）
   - variantDimensions（type / size / state / shape）
   - tokensConsumed
   - sourceEvidence（文件名 / URL / 行号）
5. 提取 token（颜色变量、字号、间距、圆角）
6. 写入 `source-brief.json`（临时文件，路径 `<output>/.cache/source-brief.json`）

## Phase 2: Token 规范化

1. 读取 `source-brief.json`
2. 生成 `colors_and_type.css`：
   - 头部加 `/* @dark-only */` 与分组优先级注释
   - token 按 group 顺序排列（surface → brand → status → text → border → font → radius → spacer）
   - verbatim 命名（不重命名）
3. 生成 `css.json`：4 个必填桶（`color`/`font`/`radius`/`spacing`）+ 2 个保留空桶
4. 自检：所有 `--bg-*`、`--text-*`、`--status-*` 必须出现在 css.json 的 color 组

## Phase 3: 组件拆解

1. 从 `source-brief.json` 取所有 24+ 组件清单
2. 对**每个组件**生成：
   - `components/{slug}.json`（schemaVersion=2，所有必填字段）
   - `preview/component-{slug}.html`（含预览 chrome + 标记区间内的 `.ds-*` CSS）
3. **必须包含 `atoms` 组件**（共享 layout 助手：`.row`、`.col`、`.grid-*`、`.stack-*`、`.h1/.h2/.h3`、`.text-secondary` 等）
4. 每个组件的 `tokensConsumed` 必须严格来自 Phase 2 的 token 集合
5. 24+ 组件不应少于：atoms / buttons / forms / form / menu / breadcrumb / card / tag / table / pagination / alert / avatar / progress / dialog / dropdown / popover / tooltip / notification / select / input-number / badge / empty / button-group / tabs

## Phase 4: 聚合 + UIKit

1. 运行 `scripts/extract-components-css.mjs` 生成 `components.css`
2. 生成 `components/index.json`（组件清单 + ui_kits 索引）
3. 生成 `uikit-plan.json`（核心 2 组件 + 22 个支持组件 + allowedComponents 白名单）
4. 生成 `library-consumption.json`（下游消费顺序）
5. 对每个 `--kit` 类型生成：
   - `ui_kits/{type}/index.html`（单文件 React 18 showcase，**必须使用 10+ 个组件**）
   - `ui_kits/{type}/quality-report.json`（必填字段全部填齐：`coreComponentsUsed` + `supportComponentsUsed` + `previewClassReuseRate`）
6. **生成库专属的"设计规范文档"**（参照 `trae-ui-example/SKILL.md` 和 `README.md` 范本）：
   - `<lib-root>/SKILL.md`（简洁版：Layout + Brand Essentials + Token Naming + Components 表 + UI Kits 表 + Authoring Rules + Conversation Continuity）
   - `<lib-root>/README.md`（人类友好版：Open the Showcases + What's Inside + Token Highlights + Naming Convention + Generation Notes + **Downstream Consumption Guide** + Icons + Next Steps）

   **关键**：这两份文档**必须按当前库的实际 token / 组件 / 主题填充**（不直接复制 trae-ui-example 的内容）。
   - 模板：`references/library-doc-template.md`
   - 填充源：`source-brief.json` + Phase 2 的 token + Phase 3 的组件清单

## 错误处理

| 场景 | 行为 |
|---|---|
| 来源无法解析（URL 404 / 图片损坏 / 路径不存在） | 终止 Phase 1，列出可修复项 |
| Token 命名与 Nimbus Core 契约冲突 | 拒绝写入，要求二选一：verbatim / 重命名 |
| 组件 CSS 缺少 `@component-css-start` 标记 | 警告并跳过该组件，但保留 preview HTML |
| 已有库根但 components.css 缺失 | 提示先运行 `refine-library` 重生成 |
| 输出目录非空 | 询问 `--force` 后覆盖；默认拒绝 |
| `tokensConsumed` 引用未定义 token | 报错，列出未定义 token，阻止写入 |
| UIKit 缺少 quality-report.json | 报错，UIKit 不算完成 |
