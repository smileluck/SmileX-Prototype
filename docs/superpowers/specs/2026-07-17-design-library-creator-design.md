# design-library-creator — 设计文档

**日期**：2026-07-17
**状态**：草案待审
**作者**：Brainstorming 会话

## 1. 目标

创建一个 `design-library-creator` 技能（位于 `.agents/skills/design-library-creator/`），从任意 UI 来源（本地源码 / 任意网站 / 图片 / 主流组件库）解析出设计 token 与组件结构，并生成**严格符合 `trae-ui-example/` 契约**的设计系统包。

## 2. 核心定位

| 维度 | 取值 |
|---|---|
| 名称 | `design-library-creator` |
| 放置位置 | `.agents/skills/design-library-creator/` |
| 子命令数量 | 4（主子令 + 3 个子令） |
| 默认输出路径 | `./design-systems/{name}/` |
| 指令风格 | **仅约束型**（SKILL.md 只写"必须/禁止"原则，AI 主导具体步骤） |
| 解析工具依赖 | 零额外安装：使用现有 Read/Grep/Glob + integrated_browser MCP + 内置视觉能力 |

## 3. 4 个子命令

| 子命令 | 文件 | 触发场景 |
|---|---|---|
| `design-library-creator` | `SKILL.md` | 从零创建整套设计系统（tokens + components + ui_kits） |
| `refine-library` | `commands/refine-library.md` | 修改已有库的 token（颜色/字体/命名/分组） |
| `expand-components` | `commands/expand-components.md` | 追加新组件到已有库 |
| `generate-additional-kit` | `commands/generate-additional-kit.md` | 追加新 ui-kit（如 mobile、marketing） |

每个子命令必须先确认目标库根路径；不存在时自动路由到主命令创建。

## 4. 工作流（4 阶段流水线）

### Phase 1: 来源解析（Source Ingestion）

**输入**：
- 本地源码路径（项目目录、组件库 dist）
- URL（任意网站）
- 图片文件（设计稿、截图）
- 组件库标识（Element Plus / Ant Design / MUI / Tailwind / UnoCSS / Chakra / Naive UI）

**解析策略**（依赖来源类型选择适配器）：

| 来源类型 | 适配器 | 实现机制 |
|---|---|---|
| 本地源码（CSS / Tailwind config / 组件库 dist） | `source-local` | Node 脚本（`postcss` + AST 解析）+ Read/Grep/Glob 直接读文件 |
| 任意 URL / 网站 | `source-url` | `integrated_browser` MCP：navigate → snapshot → evaluate JS 取 CSSOM → screenshot |
| 图片（PNG / JPG / SVG） | `source-image` | Read 工具读图 → 多模态视觉理解 → 取色/布局分析 |
| 主流组件库 | `source-library` | 内置适配器表（`references/source-adapters.md`），按库名直接读 dist 主题 |

**产出**：`source-brief.json`（中间描述，含 token 候选值、组件分类清单、视觉锚点）。**该文件不进库**，仅供后续阶段消费。

### Phase 2: Token 规范化

**输入**：`source-brief.json`

**产出（直接写入目标库根）**：
- `colors_and_type.css` —— token 权威源，verbatim 保留源命名
  - 必须包含头部注释：`/* @dark-only */`（除非用户明确要 light 主题）
  - 必须包含分组优先级注释：`/* @group-priority: brand-green, status, brand-blue, brand-purple, brand-yellow */`
- `css.json` —— 机器可读 token 投影
  - 必须字段：`color`、`font`、`radius`、`spacing`
  - 保留空桶：`shadow`、`size`（按 spec 保留）

**硬约束**：
- ❌ 禁止重命名 token（保留源命名）
- ❌ 禁止新增色彩刻度
- ❌ 禁止引入 `--color-*` 等便携别名（按 Nimbus Core 规范）
- ✅ 组件直接消费 `var(--bg-*)`、`var(--text-*)`、`var(--status-*-*)`

### Phase 3: 组件拆解

**输入**：`source-brief.json` + Phase 2 的 tokens

**产出**：
- `components/{slug}.json` —— 1 个组件 1 个 JSON 契约
  - 必须包含字段：`schemaVersion: 2`、`slug`、`name`、`category`、`tokensConsumed`、`domAnatomy`、`provenance`
  - 推荐字段：`variantDimensions`、`representativeVariants`、`structurePatterns`、`usageHints`、`doNotInvent`、`unknowns`
- `preview/component-{slug}.html` —— 1 个组件 1 个预览页
  - `<head>` 必须包含：`<link rel="stylesheet" href="../colors_and_type.css" />` + JetBrains Mono Google Fonts link
  - `<style>` 分两块：
    - **预览页 chrome**（reset、body padding、`.pv-*` 类）放在 `/* @component-css-start */` 之上
    - **组件 CSS**（`.ds-*` 类）放在 `/* @component-css-start */` 与 `/* @component-css-end */` 之间
  - 不允许外部 API 调用，纯静态 HTML

**组件命名规则**：
- 类前缀统一 `.ds-*`（design system）
- 变体用 BEM：`--{intent}`、`--{size}`、`--{state}`

### Phase 4: 聚合 + UIKit 生成

**脚本**：`scripts/extract-components-css.mjs`（Node，单一职责）

**职责**：
1. 扫描 `preview/component-*.html`
2. 提取每个文件中 `/* @component-css-start */` 与 `/* @component-css-end */` 之间的 CSS
3. 按 Nimbus Core 的区块标记（`── Buttons ──` 等）分段聚合
4. 写入根目录 `components.css`
5. 顶部加注释：`/* AUTO-GENERATED by extract-components-css.mjs — do not edit by hand */`

**额外产出**：
- `components/index.json` —— 组件清单（slug + name + preview 路径）+ ui_kits 索引
- `uikit-plan.json` —— 核心组件（fixed slots）+ 支持组件（scenario-based）
- `library-consumption.json` —— 下游消费顺序
- `ui_kits/{type}/index.html` —— 每个 ui-kit 一个单文件 React 18 showcase
  - 引用 `../../colors_and_type.css` + `../../components.css`
  - 渲染图标通过 `../../assets/icons/*.svg`
  - 容器 `max-width: 1184px`（**硬约束**：UIKit 是 showcase，不是 page template）
  - 使用 Babel Standalone CDN + `<script type="text/babel">`
- `ui_kits/{type}/quality-report.json` —— 必填字段：
  - `kitType`、`screensGenerated`、`coreComponentsUsed`、`supportComponentsUsed`
  - `previewClassReuseRate`、`inventedComponents`、`interactiveStatesRendered`
  - `primaryActionPerScreen`、`mockDataDensity`、`warnings`

## 6. 边界与不做的事（Out of Scope）

- ❌ 不修改 `trae-ui-example/`（只读参考）
- ❌ 不自动生成 light 主题（除非用户明确要求）
- ❌ 不替换图标库（沿用源；缺图时从 `assets/icons/` 补齐）
- ❌ 不支持运行时主题切换（仅静态 CSS 变量）
- ❌ 不发布 npm 包（只生成库目录，由用户自行发布）

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 来源无法解析（URL 404 / 图片损坏） | 终止 Phase 1，给出修复建议 |
| Token 命名与契约冲突 | 拒绝写入，要求用户二选一：verbatim / 重命名 |
| 组件 CSS 缺少 `@component-css-start` 标记 | 警告并跳过，但保留 preview HTML |
| 已有库根但 components.css 缺失 | 提示先运行 `refine-library` 重生成 |
| 输出目录非空 | 询问 `--force` 后覆盖；默认拒绝 |

## 8. 测试策略

- **单元**：3 个 fixture 库（Tailwind config / Element Plus / 任意网站截图）
- **契约**：生成的 `components/{slug}.json` 必须通过 schema 校验（`schemaVersion: 2` 必填字段非空）
- **视觉**：生成的 `preview/component-*.html` 必须可双击在浏览器打开无 JS 错误
- **聚合回归**：`components.css` 行数应等于各 preview CSS 区块行数之和（容差 ±2）

## 9. 验收标准

1. ✅ 提供 Tailwind 默认主题源码 → 生成 `design-systems/tailwind-core/` 结构与 `trae-ui-example/` 一致
2. ✅ 提供 Element Plus 官网 URL → 生成 `design-systems/element-core/` 24+ 组件 + 1+ ui-kit
3. ✅ 提供一张深色 IDE 截图 → 生成 `design-systems/ide-minimal/` ≥ 8 组件 + 1 ui-kit（dev-explorer 类）
4. ✅ 在已有库上运行 `expand-components tooltip` → 追加 `components/tooltip.json` + `preview/component-tooltip.html`，`components.css` 自动重生成
