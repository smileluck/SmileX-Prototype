## 1 引言

### 1.1 编写目的

本说明书旨在明确"通用业务管理系统（GenericBiz）"的功能范围、性能指标、约束条件及验收标准，作为后续设计、开发、测试与验收的基线依据。预期读者包括：项目经理、产品经理、架构师、开发工程师、测试工程师、运维工程师以及业务方代表。

### 1.2 项目背景

随着企业数字化转型的推进，传统的纸质或分散式办公模式已无法满足高效协同的需求。GenericBiz 系统通过整合任务管理、流程审批、数据采集与统计可视化等核心能力，帮助组织实现业务全流程在线化、可视化与智能化。

### 1.3 定义与缩写

| 术语/缩写 | 全称 | 含义 |
|-----------|------|------|
| SRS | Software Requirements Specification | 软件需求规格说明书 |

| CRUD | Create/Read/Update/Delete | 增删改查 |

## 2 项目概述

### 2.1 产品描述

GenericBiz 是一套面向中小型组织的通用业务管理系统，提供从"任务创建 → 流程审批 → 数据沉淀 → 可视化分析"的一体化能力。系统以 Web 端为主，预留移动端扩展能力，可作为组织的"业务中台"快速承接各类业务场景。

### 2.2 产品功能概览

系统主要由以下 5 大功能域组成：

1. **组织与权限管理**：组织架构、角色、用户、菜单与数据权限。
2. **任务与流程中心**：任务创建、流转、审批、催办、归档。
3. **数据资产管理**：表单设计、数据录入、查询、导入/导出。
4. **统计与可视化**：仪表盘、报表、图表、订阅推送。
5. **系统配置与扩展**：字典、日志、消息中心、开放接口（Open API）。

### 2.3 用户特点

| 用户类型 | 描述 | 关键诉求 |
|----------|------|----------|
| 系统管理员 | 负责系统初始化、权限分配 | 灵活、易追溯、可批量 |
| 业务主管 | 查看团队进度、审批关键事项 | 全局视角、移动审批 |
| 普通员工 | 处理日常任务、提交数据 | 简单、即时通知 |
| 外部协作者 | 有限参与指定流程 | 免登录链接、安全可控 |

### 2.4 运行环境

- **服务器端**：Linux（CentOS 7+ / Ubuntu 20.04+），CPU 4 核及以上，内存 8GB 及以上。
- **数据库**：MySQL 8.0 / PostgreSQL 14+（主库 + 至少 1 个只读副本）。
- **缓存**：Redis 6.0+。
- **客户端**：Chrome 100+、Edge 100+、Firefox 100+；屏幕分辨率 1366×768 及以上。
- **网络**：内网千兆；公网访问需 HTTPS，单用户带宽 ≥ 2Mbps。

### 2.5 设计与实现的限制

1. 浏览器端需兼容主流 Chromium 内核浏览器，不支持 IE。
2. 对外接口需遵循 RESTful 规范，鉴权使用 JWT。
3. 不得在系统中存储明文口令与个人敏感隐私信息。
4. 二次开发须遵循平台插件协议，禁止直接修改核心包代码。
5. 所有时间字段统一存储 UTC，业务层按用户时区展示。

## 3 功能需求

### 3.1 功能划分

| 编号 | 功能模块 | 优先级 | 描述 |
|------|----------|--------|------|
| F-01 | 用户与权限 | P0 | 用户、角色、菜单权限管理 |
| F-02 | 任务中心 | P0 | 任务的创建、指派、流转、归档 |
| F-03 | 流程审批 | P0 | 多分支审批、节点配置、加签/转签 |
| F-04 | 数据表单 | P1 | 表单设计、版本管理、数据采集 |
| F-05 | 统计报表 | P1 | 仪表盘、图表、订阅导出 |
| F-06 | 消息通知 | P1 | 站内、邮件、企微/钉钉 Webhook |
| F-07 | 系统配置 | P2 | 字典、日志、参数、备份恢复 |
| F-08 | 开放 API | P2 | OAuth2.0 授权的 RESTful 接口 |

> **优先级说明**：P0 = 必做（MVP 必交付）；P1 = 应做（V1.0 应交付）；P2 = 可做（视资源排期）。

### 3.2 功能详述（示例）

#### 3.2.1 F-01 用户与权限

- **用例编号**：UC-001
- **用例名称**：创建用户
- **参与者**：系统管理员
- **前置条件**：管理员已登录并具备"用户管理"权限。
- **基本流**：
  1. 管理员进入「系统管理 → 用户管理」页面。
  2. 点击「新建用户」按钮，弹出表单。
  3. 填写账号、姓名、手机号、邮箱、所属部门、角色等信息。
  4. 提交后系统校验字段合法性，校验通过后写入数据库。
  5. 系统记录操作日志，并通过邮件/短信将初始密码下发给用户。
- **后置条件**：新用户可使用初始密码登录。
- **异常流**：
  - 账号重复 → 红色提示："该账号已存在"。
  - 邮箱格式错误 → 表单校验不通过，定位到字段。
  - 短信下发失败 → 仅记录日志，不阻塞主流程；管理员可手动重发。

#### 3.2.2 F-02 任务中心

- **用例编号**：UC-010
- **用例名称**：创建并指派任务
- **参与者**：任意已登录用户
- **前置条件**：用户具备任务创建权限。
- **基本流**：
  1. 用户在「任务中心」点击「新建任务」。
  2. 填写任务标题、描述、优先级、截止时间、负责人、协作人。
  3. 可上传附件（≤ 50MB/文件，≤ 10 个文件）。
  4. 提交后系统生成任务编号（如 T-20260608-0001），并通知负责人。
- **后置条件**：任务进入"待处理"状态，负责人收到通知。
- **异常流**：
  - 截止时间早于当前时间 → 提示并阻止提交。
  - 负责人离职或无权限 → 提示并提供"切换负责人"操作。

#### 3.2.3 F-03 流程审批

- **用例编号**：UC-020
- **用例名称**：发起审批
- **参与者**：业务用户
- **基本流**：
  1. 用户选择审批模板（请假、报销、用车等）。
  2. 系统根据模板动态渲染表单。
  3. 用户填写并提交后，流程按照预设节点流转。
  4. 当前节点审批人收到待办提醒；审批人同意/拒绝/加签后流转至下一节点。
- **后置条件**：流程结束，申请人收到结果通知，审批单归档。
- **异常流**：
  - 审批人长时间未处理 → 系统按 SLA 自动催办，超时自动跳过或转交。
  - 节点被驳回 → 申请人可重新编辑提交或撤销。

> 其它功能（F-04 ~ F-08）的描述采用相同的用例模板进行展开，详细内容见附录 B《用例规约全集》。

## 4 非功能需求

### 4.1 性能需求

| 指标 | 目标值 |
|------|--------|
| 首屏加载时间（PC，4G 网络） | ≤ 2.0 秒 |
| 列表页查询响应时间 | ≤ 1.0 秒（10 万条数据） |
| 接口平均响应时间 | ≤ 300 毫秒 |
| 并发用户数 | ≥ 500 |
| CPU 平均使用率（峰值） | ≤ 70% |

### 4.2 安全性需求

1. **鉴权**：使用 JWT + 刷新令牌机制，令牌有效期 30 分钟，刷新令牌 7 天。
2. **传输**：全站 HTTPS，禁用 TLS 1.0/1.1。
3. **存储**：敏感字段（身份证、银行卡、手机号）入库前加密（AES-256）。
4. **审计**：关键操作记录审计日志，保留不少于 180 天。
5. **防护**：具备防 SQL 注入、XSS、CSRF、暴力破解的措施。
6. **风控**：登录、密码修改、权限变更需二次确认或验证码。

### 4.3 可靠性需求

- 系统年可用性 ≥ 99.9%（含计划内停机）。
- 关键服务具备主备切换能力，RTO ≤ 15 分钟，RPO ≤ 5 分钟。
- 每日全量备份，每小时增量备份，备份保留 30 天。
- 单点故障不应导致全站不可用。

### 4.4 可用性需求

- 关键操作 3 步以内可达。
- 错误信息使用用户可理解的中文，避免暴露技术细节。
- 提供新手指引、上下文帮助与快捷键。
- 支持键盘导航与无障碍基础（ARIA）。

### 4.5 兼容性需求

- 浏览器：Chrome、Edge、Firefox 最新两个大版本。
- 屏幕：1366×768 及以上分辨率自适应，最大支持 4K。
- 数据库：同时支持 MySQL 与 PostgreSQL（通过 ORM 屏蔽差异）。

### 4.6 可维护性需求

- 代码注释率不低于 25%，公共组件单测覆盖率不低于 70%。
- 核心模块采用"开闭原则"设计，便于插件化扩展。
- 提供完善的 OpenAPI 文档与 SDK。
- 日志分级（DEBUG/INFO/WARN/ERROR），关键链路具备 TraceId。

### 4.7 可移植性需求

- 部署支持物理机、虚拟机、容器（Docker / Kubernetes）。
- 配置项外置，通过环境变量或配置中心注入。
- 平台无关：核心逻辑不依赖特定 OS API。

## 5 外部接口需求

### 5.1 用户接口

- 整体风格遵循「简洁、克制、统一」的设计语言。
- 主色：#1677FF（蓝）；辅色：#52C41A（成功）、#FF4D4F（错误）。
- 字体：PingFang SC / Microsoft YaHei / 系统默认无衬线字体。
- 关键操作需提供二次确认。

### 5.2 硬件接口

无特殊硬件接口需求。后续如需对接扫码枪、打印机、U盾等设备，需另行评估。

### 5.3 软件接口

| 接口名称 | 协议 | 用途 |
|----------|------|------|
| SSO 单点登录 | OAuth2.0 / SAML 2.0 | 接入企业身份源 |
| 短信网关 | HTTP（厂商 SDK 适配） | 发送验证码、通知 |
| 邮件服务器 | SMTP | 发送通知、报表订阅 |
| 钉钉/企微 | Open API + Webhook | 消息推送 |
| 文件存储 | S3 兼容协议 | 附件、图片 |

### 5.4 通信接口

- 默认 HTTPS，RESTful + JSON。
- 鉴权头：`Authorization: Bearer {access_token}`。
- 接口版本通过 URL 前缀管理，如 `/api/v1/...`。
- 列表接口支持分页（`page` / `pageSize`）与字段排序（`sort`）。

## 6 数据需求

### 6.1 数据规模

- 首年用户数 ≤ 5,000；任务单据数 ≤ 200 万；附件存储 ≤ 500GB。

### 6.2 数据字典（节选）

| 表名 | 字段 | 类型 | 说明 |
|------|------|------|------|
| sys_user | id | BIGINT | 主键 |
| sys_user | username | VARCHAR(64) | 登录账号，唯一 |
| sys_user | password | VARCHAR(128) | BCrypt 加密 |
| sys_user | status | TINYINT | 0=禁用 1=启用 |
| tb_task | id | BIGINT | 主键 |
| tb_task | code | VARCHAR(32) | 业务编号 |
| tb_task | status | TINYINT | 1=待处理 2=进行中 3=已完成 4=已关闭 |
| tb_task | owner_id | BIGINT | 负责人 |

### 6.3 数据归档

- 单据类数据保留不少于 5 年。
- 超过保留期限的数据需经合规审批后归档或销毁。
- 用户主动删除的记录进入"回收站"，30 天内可恢复。

### 6.4 数据迁移

- 系统需提供初始化脚本、测试数据生成器与历史数据导入工具。

## 7 验收标准

1. 所有 P0 功能用例 100% 通过。
2. P1 功能用例通过率 ≥ 95%。
3. 性能、安全、兼容性测试全部达标。
4. 无 P0、P1 级缺陷遗留。
5. 文档齐备：需求、设计、测试、部署、用户手册。
6. 通过第三方安全渗透测试。
7. 完成至少一轮 UAT 用户验收测试并由业务方签字确认。
